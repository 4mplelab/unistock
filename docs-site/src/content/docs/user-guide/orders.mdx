## 注文一覧

![注文一覧画面](/docs/screenshots/orders-list.jpg)

サイドバーの「注文」に、連携ショップから検知した注文が並びます。バックエンドが一定間隔でショップをポーリングし、新しい注文や状態変化(発送確定・キャンセル等)を自動で取り込みます。今すぐ確認したい場合は画面右上の「今すぐ同期」を使います(自動取得の間隔は管理者が[設定画面](/docs/admin-guide/settings/#注文データ取得)で変更できます)。

状態バッジはショップ側の実際の状態をそのまま表示しています。

| バッジ | 意味 |
|---|---|
| <Badge text="入金待ち" variant="caution" /> | 入金が確認できていない(BASEの後払い等) |
| <Badge text="未対応" variant="caution" /> | 入金済みで、まだ発送していない |
| <Badge text="配送中" variant="note" /> | 発送済み、まだ配達完了していない |
| <Badge text="対応済" variant="success" /> | 発送・対応が完了した |
| <Badge text="対応開始前" variant="default" /> | まだ対応を始めていない状態(お届け日指定等) |
| <Badge text="キャンセル" variant="danger" /> | 注文がキャンセルされた |

注文IDをクリックすると、その注文に関する[在庫変動履歴](/docs/user-guide/history/)が開きます。外部リンクアイコンからは、連携ショップの管理画面でその注文を直接開けます(同一プラットフォームの他ショップがあり判別できない場合はこのリンクは表示されません)。「対応開始前」の注文には、状態バッジの下に「ピッキング」へのショートカットリンクが表示されます。

一番右の「金額」列には、その注文の合計金額(送料・代引き手数料・割引を含み、キャンセル済み商品は除外済み)が表示されます。この機能の追加より前に発送確定済みだった注文は「-」のままになります(発送確定前の注文は、次に状態が確認されたタイミングで自動的に埋まります)。

一覧の上部には「キャンセル済み注文を表示」「キャンセル済み商品を表示」の2つの切り替えスイッチがあります。前者は注文全体がキャンセルされたもの、後者は注文の中の一部の商品だけがショップ側でキャンセルされたもの(商品名の横に「キャンセル」バッジが付きます)をそれぞれ独立して表示/非表示にできます。どちらも初期状態は表示です。

<Aside type="note">
	これらの表示切り替えは印刷(PDF出力)にもそのまま反映されます。一方でピッキング画面は、キャンセル済みの商品を見る必要がないため常に非表示で、切り替えはありません([ピッキング](#ピッキング)を参照)。
</Aside>

## 手動管理ショップでの注文登録

[手動管理ショップ](/docs/admin-guide/shops/#手動管理への切り替え)(BASEのような外部連携APIを持たないサイト向け)を選択している場合、画面右上のボタンが「今すぐ同期」の代わりに「CSVインポート」「手動で注文を追加」になります。

- **手動で注文を追加**: 顧客情報(姓・名・都道府県・住所・メールアドレス、すべて任意)と商品行(商品・種類・数量)を入力して1件ずつ登録します。価格は商品/バリエーションに登録した価格から自動計算されます
- **CSVインポート**: 複数件をまとめて登録します。列名は自由で、他サイトからエクスポートしたCSVをそのままアップロードできます

<Aside type="note">
	[バリエーション](/docs/user-guide/manual-items/#編集画面とバリエーション)を持つ商品は、どちらの方法でも必ずいずれかのバリエーションを指定する必要があります(未指定のまま登録しようとするとエラーになります)。バリエーションを持つ商品は共通の価格・在庫を持たず、価格・在庫はすべてバリエーションごとに個別に管理されるためです。
</Aside>

<Steps>

1. ダイアログにCSVファイルをドロップ(またはクリックして選択)します。1行目が項目名(ヘッダー)ではなくデータそのものの場合は、「1行目を項目名として扱う」のスイッチをオフにしてください(オフにすると列名は「列1」「列2」…という仮の名前になります)
2. 列の対応付け画面で、CSVの各列を「商品コード」「数量」「姓」のようなUniStockの項目に割り当てます(選んだ列の実際の値がその場でプレビューされます)。商品コードのみ必須です。同じ値の行を1つの注文(複数商品)としてまとめたい場合は「注文グループ化キー」も割り当ててください(未指定なら1行=1注文)
3. よく使う対応付けは名前を付けて保存できます。次回からは保存した設定を選ぶだけで、列の対応付けをやり直す必要がありません
4. 「インポート実行」で取り込みます。結果画面に新規作成件数とエラー件数(行番号付き)が表示されます

</Steps>

<Aside type="tip">
	列の対応付けの練習には、正常データ・エラーデータの両方を含む[サンプルCSV](/docs/samples/manual-orders-sample.csv)を使えます(デモモードで作成される「商品管理(手動)」のデモ商品を参照する内容です)。
</Aside>

登録した注文のうち「対応開始前」のものには、状態バッジの下に「編集」「発送済みにする」「キャンセルする」が表示されます。「編集」では商品明細・顧客情報を丸ごと修正でき、既存の部品引当は安全に解放してから作り直されます。発送確定・キャンセル済みの注文は編集できません。

<Aside type="note">
	手動管理ショップの注文も、部品の引当・ピッキング・印刷・売上集計は、BASEショップの注文と全く同じ仕組みで扱われます。
</Aside>

## 部品の引当

注文が確定すると、商品に登録されたBOMに従って部品在庫が自動的に仮引当されます。

<FlowDiagram
	steps={[
		{ label: "注文検知", sub: "仮引当(在庫は減らさない)", tone: "order" },
		{ label: "発送確定", sub: "仮引当→実消費", tone: "order" },
		{ label: "対応済", tone: "order" },
	]}
/>

<Steps>

1. 注文検知時、商品のBOMに従って部品在庫を仮引当する(まだ実際には減らさない)
2. 発送が確定すると、仮引当が実際の在庫消費に変わる
3. キャンセルされると、引当が解除される(未消費分は在庫に戻る)

</Steps>

<Aside type="caution" title="引当スキップ">
	BOMが未設定、または該当するBOM行が見つからない商品は引当がスキップされ、[イベントログ](#イベントログとの連携)に記録されます。BOMを後から整備すれば、次回の同期時に自動で引当がリトライされます(過去に確定済みの注文は遡って補正されません)。
</Aside>

## ピッキング

![ピッキング画面](/docs/screenshots/picking.jpg)

サイドバーの「ピッキング」では、未発送の注文について実際に部品を集める作業を管理します。上部の「残りの必要数量」カードには、未対応の注文のうちピッキング未完了分を部品/中間品ごとに集計した合計数が表示されます。各注文カードには「ピッキング完了」「○/○ 完了」等の進捗バッジが表示され、商品ごとにチェックを入れて完了を記録できます。全商品がピッキング完了した注文カードは背景色が変わります。

<Aside type="note">
	ショップ側で商品単位にキャンセルされた行は、集める必要がないため常に非表示になります(注文一覧と違い、表示切り替えはありません)。注文内の商品が全てキャンセルされた場合は、その旨のメッセージだけが表示されます。
</Aside>

<Aside type="note">
	ピッキングのチェックは表示上のフラグであり、在庫や引当には一切影響しません。実際の発送確定はショップ側の状態に従います(ピッキングを完了しても、発送するまでは注文一覧の状態は「未対応」のままです)。
</Aside>

<Aside type="caution">
	部品の自動引当ができていない商品には「BOM未設定など、自動引当できていません(次回同期時に再試行されます)」という警告が表示されます。原因はBOM編集画面や[イベントログ](/docs/user-guide/history/)から確認できます。
</Aside>

## 印刷・PDF出力

印刷できる場所は2つあり、独立した機能です。

- **注文一覧の「印刷」**: 選択モードで注文にチェックを入れ、「ピッキング内容も含める」を選んでPDFを出力します。BOM側で「オプションを横並びの表にする」設定をした商品はExcel風のマトリクス表、それ以外はカード形式で出力され、同一PDF内に混在できます(混在する場合、対象の注文には「他商品あり」の印が付きます)
- **ピッキング画面の「印刷」**: 表示中のピッキングカードをブラウザの印刷機能でそのまま印刷します。全体をまとめて選択して印刷することも、注文カードごとに個別印刷することもできます

## イベントログとの連携

引当スキップ・在庫操作の失敗など、確認が必要な業務イベントは「イベントログ」に記録されます。注文一覧・BOM編集画面には該当するイベントログへのリンクが表示されるので、そこから直接原因(BOM未設定の商品名など)を確認できます。詳しくは[在庫変動履歴とイベントログ](/docs/user-guide/history/)を参照してください。
