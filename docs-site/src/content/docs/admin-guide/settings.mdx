サイドバー下部の「設定」からシステム全体の設定を行います。

![設定画面](/docs/screenshots/settings.jpg)

## 注文データ取得

連携ショップから注文を自動取得する間隔(秒)を設定します。「運用開始日時」を指定すると、それ以前の注文は同期対象外になります(未設定の場合は初回同期時点が使われる)。

## データ管理

- **注文履歴のみ消去**: 一時的に無効化しています。注文データは売上・原価を計算できる唯一の記録で、行ごと削除すると再現できなくなるため、氏名・住所・メールアドレスだけを消す方式に置き換えるまでの措置です
- **全データを消去**: 部品・中間品・BOM・注文・発注・手動管理ショップの商品など業務データを全て削除します(ショップ自体・連携の認証情報・この設定自体は消えません)

<Aside type="tip" title="全データを消去はいつ使う?">
	[デモモードとサンプルデータ](/docs/admin-guide/demo-mode/)の`scripts/seed_demo_data.py`でサンプルデータを投入した後、本番運用を始める前にリセットしたい場合などに使います。`DEMO_MODE=true`のデモモードとは別の機能で、デモモード中はこのボタン自体が無効化されます(デモ用のサンプルデータを保護するため)。デモモードからの切り替えは、`.env`の`DEMO_MODE`をfalseに戻すだけで自動的にデータが全消去されます。
</Aside>

## 自動データ削除

完了済みの履歴データを、指定した日数を過ぎたら自動的に削除する設定です。24時間おきに実行され、未対応の注文・未入荷の発注など進行中のデータは対象外です。項目ごとに空欄にすると、その種類は削除しません。

- 発注履歴(入荷済み/キャンセル済みのみ)
- リストック予約履歴(実行済み/キャンセル済みのみ)
- 部品・中間品の在庫変動履歴
- イベントログ

<Aside type="note">
	注文履歴はこの一覧に含まれません(上記の「注文履歴のみ消去」と同じ理由で一時的に対象外です)。
</Aside>

## 通知

発注点割れなどの業務イベントを、Webhook・メールで外部に通知します。通知対象は5種類あり、それぞれ「Webhook」「メール」を個別にON/OFFできます(片方だけでも、両方でも構いません)。

画面上部の「設定対象」で「共通」(全ショップの既定値)か、連携中のショップのいずれかを選びます。共通の設定がベースになり、ショップを選んだ場合はそのショップだけの上書き(Webhook URL・メールアドレス・カテゴリごとのON/OFF)を追加で設定できます。未入力/「継承」の項目は共通設定にフォールバックします。この選択はヘッダーのショップ切り替えとは独立しています。

1. 部品が発注点を下回った(中間品には発注点の概念自体がありません)
2. 発注(仕入れ)の予定納期を過ぎても未入荷
3. 商品の作成可能数が閾値を下回った(閾値は[BOM編集画面](/docs/user-guide/bom/)で商品ごとに設定します)
4. 外部連携の認証エラー(同期停止)
5. 在庫操作の失敗(発送時の在庫消費処理エラー)

<Aside type="note" title="通知のタイミング">
	発注点割れ・納期超過・作成可能数閾値割れは、条件を初めて満たした瞬間だけ通知します(条件を満たしたままの間は毎回通知しません)。一度解消した後、再び条件を満たした場合は改めて通知されます。
</Aside>

<Aside type="caution" title="デモモードでは送信されません">
	デモデータに対して実際のWebhook/メールが飛ぶのを防ぐため、デモモード中は通知機能自体が動作しません。
</Aside>

### 複数ショップ運用時の配信ルール

部品の発注点割れは特定のショップに属さないイベント(在庫が全ショップ共有のため)ですが、各ショップの設定(上書きが無ければ共通設定)に従って配信されます。共通設定と送信先が重複する場合(例: どのショップも上書きしておらず共通設定のままの場合)は1通にまとめられ、二重に届くことはありません。

### Webhookとは

「Webhook」は、SlackやDiscordなどのチャット/チームツール側が発行する専用のURLです。UniStockはそのURL宛てに「発注点を下回りました」といったメッセージをHTTPで送るだけで、チャット側の新規アプリ登録や複雑な認証は不要です。1つのURLにつき投稿先(チャンネル)が1つ固定されるので、通知したいチャンネルの数だけURLを発行して設定画面に貼り付けてください。設定画面には5プラットフォーム分のURL欄があり、複数登録しておくと登録済みの全プラットフォームへ同時に送信されます。

以下、各プラットフォームでURLを取得する手順です。URLは他人に知られると誰でもそのチャンネルに投稿できてしまうため、外部に公開しないよう注意してください。

<Aside type="tip" title="テスト送信で動作確認できます">
	各URL欄・メールアドレス欄の右にある「テスト送信」ボタンで、保存前でもその場でテスト通知を送れます。成功するとボタンが一瞬「✓ 送信完了」に変わり、失敗すると理由(URLが間違っている、SMTP未設定 等)が赤字でボタンの下に表示されたままになります。実際に発注点割れ等が起きるのを待たずに設定を確認できます。
</Aside>

#### Slack

<Steps>
1. [api.slack.com/apps](https://api.slack.com/apps) を開き、「Create an App」→「From scratch」を選ぶ
2. アプリ名を入力し、通知先にしたいワークスペースを選んで「Create App」
3. 左メニュー「Features」→「Incoming Webhooks」を開き、「Activate Incoming Webhooks」をONにする
4. 「Add New Webhook to Workspace」を押し、投稿先チャンネルを選んで許可する
5. 「Webhook URLs for Your Workspace」に表示されるURL(`https://hooks.slack.com/services/...`)をコピーし、UniStockの設定画面の「Slack」欄に貼り付ける
</Steps>

#### Discord

<Steps>
1. Discordでサーバー名の右の▼→「サーバー設定」を開く
2. 左メニュー「連携サービス」→「ウェブフックを作成」
3. 名前と投稿先チャンネルを設定する
4. 「ウェブフックURLをコピー」でURLを取得し、「変更を保存」を押す
5. コピーしたURL(`https://discord.com/api/webhooks/...`)をUniStockの設定画面の「Discord」欄に貼り付ける
</Steps>

#### Mattermost

<Steps>
1. Mattermostのメニュー(製品メニュー)→「インテグレーション」→「受信Webhook」を開く(表示されない場合はシステムコンソール側で受信Webhookを有効にする必要があります)
2. 「Webhookを追加」を選び、名前と投稿先チャンネルを設定して作成する
3. 発行されたURL(`https://<サーバー>/hooks/...`)をUniStockの設定画面の「Mattermost」欄に貼り付ける
</Steps>

#### Google Chat

<Steps>
1. 通知したいスペースを開き、スペース名の右の▼(スペースの詳細)→「アプリと統合」を開く
2. 「Webhook」欄の「Webhookを追加」を選び、名前を入力して保存する
3. 作成したWebhookの「その他」メニュー→「リンクをコピー」でURLを取得し、UniStockの設定画面の「Google Chat」欄に貼り付ける
</Steps>

#### Microsoft Teams(Workflows)

従来の「Incoming Webhook」(コネクタ)は2025年末で廃止されているため、代わりに「Workflows」アプリを使います。

<Steps>
1. 通知したいチャンネルの「...」メニュー→「ワークフロー」を開く
2. テンプレート検索で「Webhook要求の受信時にチャンネルに投稿する」(Post to a channel when a webhook request is received)を選ぶ
3. 投稿先のチーム・チャンネルを確認して作成する
4. 発行されたURLをUniStockの設定画面の「Microsoft Teams」欄に貼り付ける
</Steps>

### メール通知の設定(Gmailの例)

メール通知は、サーバーの`.env`にSMTP接続情報を設定して初めて有効になります(未設定のままだと、設定画面でメール通知をONにしても何も送信されません)。設定画面側で切り替えるのは「送信先メールアドレス」と有効/無効のみです。

```bash title=".env"
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=your-address@gmail.com
SMTP_PASSWORD=xxxxxxxxxxxxxxxx
SMTP_FROM_ADDRESS=your-address@gmail.com
```

<Aside type="caution" title="Gmailの通常のパスワードは使えません">
	`SMTP_PASSWORD`には、Googleアカウントの通常のログインパスワードではなく「アプリパスワード」(16桁の専用パスワード)が必要です。2段階認証を有効にしていないと発行できません。
</Aside>

<Steps>
1. Googleアカウントで2段階認証を有効にする(未設定の場合は[セキュリティ設定](https://myaccount.google.com/security)から)
2. [myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords) を開く(2段階認証が有効でないとこのページ自体にアクセスできません)
3. アプリ名を入力(例: `UniStock`)して「作成」を押す
4. 表示された16桁のパスワード(スペース抜き)をコピーする
5. `.env`の`SMTP_PASSWORD`にそのパスワードを、`SMTP_USER`/`SMTP_FROM_ADDRESS`にGmailアドレスを設定する
6. `docker compose up -d --build backend`で再起動する
</Steps>

## 部品のカラーパレット

部品の「色」項目で選べる基本色を、色名と16進カラーコードのペアで管理します。ここで登録した色が、[部品](/docs/user-guide/parts/)の色選択・一覧の色スウォッチに使われます。

## 許可ユーザー

UniStock自体へログインできるアカウントを管理します(デモモードでは表示されません。ログイン自体が無いため)。

- **識別子**: Google/Microsoft/GitHubはメールアドレス、Xはメールアドレスを取得できないため`x:ユーザーID`の形式で登録します
- **表示名**: 任意。ヘッダーのアカウント表示などに使われます
- **管理者**: オンにすると、このユーザーもショップ設定・設定画面など管理者専用の操作ができるようになります
- **削除**: 一覧の「削除」ボタンから外せます。ただし自分自身と、最後の1人残った管理者は削除できません(全員の管理者権限が無くなって誰も設定を変更できなくなる事故を防ぐため)

<Aside type="note" title="登録は事前に、ログイン前に行う">
	許可ユーザーへの追加は管理者が事前に行うもので、本人が先にログインを試みて申請する、という流れではありません。登録されていないアカウントでログインしようとすると「このアカウントにはUniStockへのアクセス権がありません」と表示され、ログインできません(詳しくは[ログイン](/docs/user-guide/login/)を参照)。
</Aside>

<Aside type="tip" title="唯一の例外: 一番最初のログイン">
	通常モードで、許可ユーザーが1人も登録されていない状態(サーバーを初めて起動した直後)に限り、最初にログインしたアカウントが自動的に管理者として登録されます。2人目以降は、先にこの画面で許可ユーザーとして登録しておく必要があります。
</Aside>

## APIキー

外部プロジェクトからログインを介さずAPIを直接呼び出すためのキーを発行・失効します。生キーは発行直後の一度しか表示されないため、その場でコピーして保管してください。
