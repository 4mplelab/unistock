UniStockには、実際のECサイトへの接続やログイン設定をせずに全機能を試せる「デモモード」があります。導入検討中の試用や、社内デモに使えます。

## デモモードを有効にする

サーバーの`.env`で`DEMO_MODE=true`にして起動します(詳しい起動手順は[README](https://github.com/4mplelab/unistock)を参照)。

![デモモードのログイン画面](/docs/screenshots/login-demo.png)

<Steps>

1. `.env`の`DEMO_MODE`を`true`にする
2. `docker compose up --build`で起動する
3. ブラウザで開くと、ログイン画面には「デモを試す」ボタンだけが表示される(Google/Microsoft/GitHub/X等のログイン設定は不要)。初回はショップが0件のため、続けてセットアップウィザードに進む(画面つきの詳細は[初回ログインとセットアップウィザード](/docs/admin-guide/first-run/)を参照)

</Steps>

<Aside type="caution">
	デモモードでは実際のBASE連携は一切行われません(BASEへの通信自体が発生しない)。設定画面の「データ消去」機能もデモ用のサンプルデータを保護するために無効化されます。
</Aside>

<Aside type="danger" title="モードを切り替えると全データが消える">
	`DEMO_MODE`を`true`⇔`false`で切り替えて起動すると、そのたびに**永続化データが全て自動削除されます**(安全のため、デモデータと本番データを同じデータベース上で絶対に共存させない設計です)。本番のBASE連携トークンが既に存在する状態で誤って`DEMO_MODE=true`にしても、起動時に自動検知して通常モードへ強制的にフォールバックするガードがあります。
</Aside>

## 注文が自動的に進む・補充される(BASEショップのみ)

デモモードは実際のBASEへ通信しないため、放っておいても注文の状態は変わりません。それでは「発送が確定して実際に部品在庫が減る」というUniStockの中心的な動きを体験できないため、[注文一覧](/docs/user-guide/orders/)の「今すぐ同期」を押すたび(自動取得が有効なら定期的にも)、デモモードだけの特別な処理が走ります。

<Aside type="note">
	この自動進行・補充はBASEショップだけの挙動です。手動管理ショップはBASEのような同期・ポーリングの概念自体を持たず(デモモードかどうかに関わらず、注文はフォーム・CSVでの登録でしか増減しません)、対象外です。
</Aside>

<Steps>

1. ピッキングが完了している(全商品にチェックが付いた)未対応の注文を、自動的に「対応済み」にする。これにより実際に部品在庫が消費され、[在庫変動履歴](/docs/user-guide/history/)にも記録される
2. その結果、未対応の注文が0件になったら、BOMに登録済みの商品からランダムに選んで、ランダムな件数(2〜5件)の新しい注文を補充する

</Steps>

<Aside type="note">
	補充された注文がたまたま「テスト商品001」で、かつオプション/種類が未選択の組み合わせになった場合、レシピ未設定の中間品(基板ユニット)に在庫が足りず引当がスキップされることがあります(イベントログに記録されます)。これも実際の「引当スキップ」機能を確認できる一例です。
</Aside>

## サンプルデータの内容

デモモードでショップを新規作成するとき(初回の[セットアップウィザード](/docs/admin-guide/first-run/)、または[ヘッダーの「+ ショップを追加」](/docs/admin-guide/shops/#ショップの追加))、BASE・手動管理どちらのプラットフォームを選んでも、部品・中間品・BOM・注文・発注のサンプルが一通り入ります。手動管理ショップにはオプション機構が無く、注文もキャンセル/発送済み以外は「未対応」までしか進まない(BASEのような入金待ち・発送準備中等の細かいステータスが無い)ため、BASE版よりデータ量・パターン数は少なめです。

<Aside type="note">
	サンプルデータの投入はショップの新規作成時のみで、既存ショップに後から追加する画面はありません。作り直したい場合は、いったん[設定画面](/docs/admin-guide/settings/#データ管理)の「データ管理」→「全データを消去」で消してから、ショップを作り直してください。
</Aside>

## 通常モードでサンプルデータだけ試したい場合

デモモードとは別に、通常モード(実際にBASEと連携する構成)のまま、動作確認用のサンプルデータだけ投入することもできます(この方法はBASEショップのみ対応。手動管理ショップのサンプルデータは、デモモードでのショップ新規作成時のみ投入できます)。

```bash
docker compose exec backend python scripts/seed_demo_data.py
```

BASEのショップが無ければ作成し、あれば使い回してそこにサンプルデータを投入します。既に投入済みの場合は何もせず終了します(二重投入防止)。試用後にサンプルデータを消したい場合は、[設定画面](/docs/admin-guide/settings/#データ管理)の「データ管理」→「全データを消去」を使ってください。
